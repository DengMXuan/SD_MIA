# Qwen3 epoch 1 KD 草稿主方法实验报告

日期：2026-09-25  
实验批次：[`qwen_kd_epoch1_condition_seed_v1`](../artifacts/audits/qwen_kd_epoch1_condition_seed_v1/reports/SUMMARY.json)  
状态：3 个数据集 × 3 个条件 seed，9/9 项完成；同条件基线尚无实测结果。

## 摘要

Qwen3-8B 目标模型与 Qwen3-1.7B 辅助数据蒸馏草稿的固定候选主方法 `main_fixed_sparse_positive`，在 WikiTection、NewsTection、ArxivTection 的 9 个条件上取得 **AUC 0.8625–0.9026**。三个数据集各自的三 seed 平均 AUC 为 **0.8726、0.8949、0.8958**；9 个条件等权宏平均为 **0.8878**。在测试集上事后选择满足 FPR 上限的 ROC 点，10% FPR 处 TPR 的三数据集均值分别为 **0.6348、0.7003、0.7063**，1% FPR 处为 **0.2265、0.2625、0.3228**。这些数值说明当前主方法在本实验的成员与非成员之间有明显区分能力；AUC 越高也意味着成员身份越容易被识别。

独立非成员校准阈值的部署口径更严格：9 个条件中有 4 个在标称 10% FPR 下的测试 FPR 超过 10%，另有 4 个在标称 1% 下超过 1%。尤其是 1% FPR 档，200 条校准样本带来较明显的跨 seed 波动，不能把测试集 ROC 点当作部署保证。

旧批次的 WikiTection、NewsTection 基线汇总已从 Git 历史恢复。在这两个数据集的 epoch 1 历史表中，AUC 最高的基线均为 `min_k_pp`（0.6914、0.7328），低于本次主方法的 0.8726、0.8949。**这只是跨批次的历史参考，不能当作新版同条件的正式方法差值。**旧批次使用错误审计 seed；ArxivTection 也没有这份旧基线汇总。

## 实验设置与指标

| 项目 | 设置 |
|---|---|
| 模型 | 目标 `Qwen/Qwen3-8B-Base`；草稿 `Qwen/Qwen3-1.7B-Base`。使用各条件已训练的 epoch 1 目标与 `draft_auxiliary_distilled` 检查点；不重新训练语言模型。 |
| 条件 | WikiTection、NewsTection、ArxivTection；每个数据集使用 1919、1949、1978 三个 seed。训练/冻结划分、主方法采集与 TCN、辅助集划分、AUC bootstrap 均使用对应条件 seed。 |
| 样本 | 每条件测试集 2,000 member + 2,000 nonmember；600 条独立审计辅助样本按 320 训练、80 验证、200 非成员校准划分。测试样本不用于检测器训练或阈值校准。 |
| 方法 | 固定候选协议，使用草稿特征和接受信息、非成员条件接受分布 TCN、正向稀疏证据及独立非成员校准；访问通道为 `draft_features_and_acceptance_only`。 |
| AUC 与 pAUC | 分数越高越像 member。`pAUC₀₋₁₀%` 是 FPR ∈ [0, 0.10] 的梯形面积除以 0.10，未做随机水平修正。 |
| 两种 TPR | `ROC TPR` 是同一测试集上，在经验 FPR 不超过 10% 或 1% 时可达到的最大 TPR，属于事后描述。`校准 TPR / 实际 FPR` 用独立 200 条非成员样本定阈值，再在测试集上测得。 |
| 不确定性 | 下表 `±` 为三个条件 seed 的**样本标准差**，不是均值的置信区间。逐条件 AUC 的文档分层 bootstrap 区间和部署率的 Wilson 区间见原始报告；部署率区间以已定校准阈值为条件。 |

方法与数据约定见[专用重跑说明](../experiments/sd_membership_sft/docs/QWEN_KD_EPOCH1_RERUN.md)和[矩阵设计](../experiments/sd_membership_sft/docs/QWEN_AUDIT_MATRIX_DESIGN.md)。

### 独立校准后的实际工作点

下表每格为 **测试 TPR / 测试实际 FPR**；标称 FPR 只决定校准阈值，不代表测试 FPR 一定等于或低于标称值。

| 数据集 | Seed | 标称 10% | 标称 1% |
|---|---:|---:|---:|
| WikiTection | 1919 | 0.6330 / 0.0875 | 0.0775 / 0.0005 |
| WikiTection | 1949 | 0.6370 / 0.1140 | 0.1605 / 0.0065 |
| WikiTection | 1978 | 0.6285 / 0.0920 | 0.2765 / 0.0140 |
| NewsTection | 1919 | 0.6230 / 0.0730 | 0.2550 / 0.0105 |
| NewsTection | 1949 | 0.7170 / 0.1070 | 0.1305 / 0.0015 |
| NewsTection | 1978 | 0.7590 / 0.1365 | 0.3350 / 0.0140 |
| ArxivTection | 1919 | 0.6915 / 0.0885 | 0.4035 / 0.0225 |
| ArxivTection | 1949 | 0.7425 / 0.1355 | 0.2810 / 0.0075 |
| ArxivTection | 1978 | 0.7080 / 0.0960 | 0.2895 / 0.0045 |

标称 10% 下，实际 FPR 范围是 7.30%–13.65%；标称 1% 下是 0.05%–2.25%。例如 ArxivTection/1919 的标称 1% 工作点测得 TPR 40.35%、FPR 2.25%；它**不能**表述为“在实际 1% FPR 下达到 40.35% TPR”。若需要部署层面的严格低误报结论，应增加独立校准样本或评估跨校准抽样的覆盖情况。

### 计算成本

报告中的计时包含准备/检测器拟合、独立校准和 4,000 条测试记录打分，并以测试记录数摊销；不含模型加载、未计时预热、归档 I/O 与指标汇总。三个数据集的平均计时分别约为 27.9、29.7、105.4 分钟，折合每条测试记录约 418、445、1581 ms。报告记录的平均 PyTorch 峰值已分配显存约为 20.0、20.0、24.2 GiB，硬件为 A100-SXM4-80GB。主方法同时使用目标和草稿；ArxivTection 每条测试记录的目标/草稿输入 token 各约 2276 个，而 WikiTection 约 590 个，与耗时差异方向一致，但这不是严格的因果分解或端到端服务延迟。

## 与基线方法的比较

仓库定义了 11 个仅访问目标模型的基线：`loss`、`min_k_prob`、`min_k_pp`、`recall`、`icp_mia`、`petal`、`sead`、`ws`、`rs`、`bt`、`samia`。本次专用入口的状态明确为 `baseline_tasks: 0`；当前工作区没有对应的新版基线 `REPORT.json`。因此可比较性的结论如下。

| 比较项 | 当前证据 | 结论 |
|---|---|---|
| 主方法在 3 数据集 × 3 seed 的 AUC、低 FPR TPR 与成本 | 9 份已校验报告 | 可报告上述实测值。 |
| Wiki/News 与旧基线的数值并列 | 已恢复的旧 CSV；其逐方法原始报告已删除 | 可作**历史参考**；不能作为当前同条件的确认性比较。 |
| 主方法减任一新版基线的 AUC、pAUC、TPR 差值 | 缺少同条件新版基线报告 | **不可计算；尚不能给出正式排名或胜出结论。** |
| 主方法与基线的耗时/显存差值 | 缺少同条件基线计时；二者模型访问范围也不同 | **不可计算。**后续应同时呈现推理访问和成本，不能只比较检测准确率。 |

旧批次按 AUC 排名最高的 `min_k_pp`，与本次主方法的**数值差**为 Wiki +0.1813、News +0.1621 AUC；归一化 pAUC₀₋₁₀% 分别为 0.1269→0.4506、0.1459→0.5092；ROC TPR @ 1% 分别为 0.0302→0.2265、0.0288→0.2625。旧 `icp_mia` 的 Wiki ROC TPR @ 1% 为 0.0337，略高于旧 `min_k_pp`，仍低于本次主方法。所有 6 个 Wiki/News seed 的主方法 AUC 数值也高于对应旧 `min_k_pp`，但这些跨批次数值差**没有配对置信区间**，不应解释为已经完成公平复现。

原因是旧审计 seed 同时决定 600 条辅助样本中的 320/80/200 划分、基线参考记录、生成类方法的随机流和 AUC bootstrap。即使测试成员/非成员来自冻结划分，旧校准阈值和部分基线分数仍与新版条件 seed 方案不同。`loss`、`min_k_prob`、`min_k_pp` 等目标侧确定性评分受此 seed 错误的影响可能较小，但旧逐方法文件已删除，无法以来源与记录哈希确认跨批次完全同构。旧耗时同样只供参考：`min_k_pp` 的 Wiki/News 历史均值约为 74.5/75.7 ms 每测试文档，本次主方法为 418.3/445.1 ms；主方法还额外访问草稿模型，不能仅凭时间差判断算法优劣。

公平的实测比较应使用同一 Qwen3 epoch 1 目标 checkpoint、冻结成员/非成员记录、三个条件 seed、独立校准口径和指标定义；基线可复用同一条件的目标与数据，但不能把 11 个基线视为 11 个独立 seed。完成新版基线后，应按“数据集 × seed × 方法”对齐报告，给出逐条件差值、三 seed 均值与波动，并对同一测试记录上的差值计算配对区间。完整 Qwen 审计入口见[运行说明](../experiments/sd_membership_sft/README.md#运行完整审计矩阵)，其范围大于本报告的 9 项主方法。
