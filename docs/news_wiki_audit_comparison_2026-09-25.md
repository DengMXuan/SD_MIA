# News/Wiki：11 个基线与固定候选主方法对比

数据来源：`artifacts/runs/audits/qwen_fixed_v1/` 下每个方法的 `REPORT.json`；生成日期：2026-09-25。
每个数据集 × epoch 使用 seed 1919、1949、1978 的算术平均。11 个目标侧基线每个条件只计一次；主方法分别显示辅助蒸馏与成员训练两种 draft。
每个 seed 的 13 个报告具有相同的记录 ID 哈希，均含 200 个独立校准非成员、2000 个测试成员、2000 个测试非成员。156 个固定候选报告的分数归档校验通过。

指标：AUC 越高越好；pAUC10 为 FPR≤10% 的面积除以 0.1，未做随机基线校正；ROC TPR 是测试集上受 FPR 上限约束的描述性点。
校准 TPR/FPR 使用独立非成员校准集定阈值；表中 `校准 TPR/FPR` 的两个数分别是测试集 TPR 与实际 FPR，不能把后者视为恰好等于标称 10% 或 1%。
表中为跨 3 seed 均值；逐 seed 的 AUC bootstrap 区间、校准率 Wilson 区间及全部原始效率字段见逐 seed CSV；所有数值字段的跨 seed 均值和标准差见汇总 CSV。
效率计时排除模型/数据加载和预热，包含方法准备、校准和测试，按 4000 个测试文档摊销；查询和 token 工作量同样按 4000 个测试文档摊销。
这些既有结果均为独立运行成本，不是新复用模式下的增量成本。主方法同时使用 target 与 draft，因此模型工作量要分别看两者。
GPU 显存是 PyTorch allocated 峰值，包含常驻模型；计时不是端到端作业耗时。

完整数据： [逐 seed CSV](news_wiki_audit_per_seed_2026-09-25.csv)；[三 seed 汇总 CSV](news_wiki_audit_three_seed_summary_2026-09-25.csv)。

## 主要观察

- 四组条件中，辅助蒸馏 draft 的固定候选主方法均有最高 AUC、pAUC10、ROC TPR@1% 和独立校准 TPR@1%。成员训练 draft 的主方法均排第二。
- 以 AUC 排名，最强基线四组都是 `min_k_pp`。其 AUC 为 news 0.733/0.984、wiki 0.691/0.952（分别为 1/3 epoch）；主方法辅助蒸馏对应为 0.895/0.999、0.872/0.996。
- wiki 的 `icp_mia` 在 pAUC10 和 ROC TPR@1% 上强于 `min_k_pp`，尤其 3 epoch：pAUC10 为 0.757 对 0.587，ROC TPR@1% 为 39.8% 对 13.4%。
- `ws`、`rs`、`bt` 的 AUC 接近 0.5；`samia` 为 0.518–0.565，同时平均需要约 3.2–4.0 秒/文档。辅助蒸馏主方法约 0.4–0.45 秒/文档，但比约 0.07–0.08 秒/文档的 `min_k_pp` 慢。
- 独立校准的实际 FPR 会偏离标称值，因此比较校准 TPR 时应同时看同一行的实际 FPR；例如 wiki 3 epoch 的 `icp_mia` 在标称 1% 下实际 FPR 为 1.5%，辅助蒸馏主方法为 0.9%。
